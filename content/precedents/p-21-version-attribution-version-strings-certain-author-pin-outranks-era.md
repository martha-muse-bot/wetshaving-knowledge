*Status: standing · Source: [[Precedents]]*

**Statement:** For a versioned product line (e.g. Claymore V1/V2/V3/Evolution),
version-specific strings resolve to their version, certain. Bare (unversioned)
strings resolve by author pin first, then maker, then era — never by
latest-model or base-model default, and never by per-post era splitting.
An author pin governs ALL of that author's bare strings for the product:
an author's version-specific string pins their bare strings before and
after it (same physical razor); an author's first bare post, resolved by
maker or era, pins their later bare strings, which are NOT re-resolved by
their own years. Confidence propagates from the pin and never upgrades:
an explicit version pin makes later bare strings certain by author scope
(P-15 hard carve-out); a loose era/maker pin keeps later bare strings
loose. An unpinned author's first bare post resolves by maker (certain
only when the maker uniquely pins the version, e.g. Alpha → Evolution),
then era (loose). What remains unresolved goes to a loose era leader
with its share recorded, or to a P-11 ambiguous line. An author with two
version pins (owns two versions) has later bare strings ambiguous between
their own pins unless context disambiguates. The rule is
backward-protective: re-runs must preserve pins, never silently era-split
an author's history when a new version appears.
**Established by:** Claymore V2/V3 attribution ruling (2026-10-28, user
tap: record it with author continuity) — user observed that an author
posting bare "Claymore" across years means the same razor, not a new
purchase per era.
**Contrast:** P-17 (model attributes) — versions that differ in geometry
are distinct models (Claymore V1 curved vs V2 angled head, P-03), so
version attribution is about WHICH model a bare string names, not about
folding versions as attributes. P-15 (loose defaults) — era defaults here
are loose and era-bounded, never certain.
**Matcher implication (future build):** needs an author-pin table consulted
before era defaults, plus era windows on loose aliases; neither exists
yet, and no build is owed until V2/V3 strings actually appear (zero in
the dataset as of 2026-10-28).
